## 文字笑话
这种方法是把笑话数据直接“打包”进插件里。你可以把这想象成在用户的背包里放了一本**《笑话大全》**。

- **工作原理：** 你在开发插件时，准备一个包含 500 或 1000 条笑话的文本文件（比如 JSON 格式）。当用户点击插件时，程序直接从这个本地文件中随机抽取一行显示。
    
- **优点：**
    
    - **速度极快：** 不需要等待网络请求，以此实现“秒开”。
        
    - **完全离线：** 没网也能看。
        
    - **完全可控：** 你可以亲自审核每一条笑话，确保没有不良内容，或者确保笑话真的好笑。
        
- **缺点：**
    
    - **内容有限：** 看完了这 1000 条，用户就会看到重复的。
        
    - **更新麻烦：** 如果你想加新笑话，必须发布插件的新版本，用户更新插件后才能看到。

## 视频：
引用/嵌入（Embed）（推荐，无需服务器）

这是大多数插件的做法。你不需要存视频文件，也不需要让用户跳走，而是把 B站的播放器“借”到你的插件窗口里。

- **体验：** 用户点击插件 -> 弹出的小窗口里**直接出现了一个 B站的小播放框** -> 用户点击播放，就在小窗口里看完，笑完关闭，继续工作。
    
- **原理：** B站（以及 YouTube、优酷等）都提供一种叫 `iframe` 的代码。这就像在你的插件上开了一扇“窗户”，窗户对面是 B站的服务器。
    
- **你的数据存什么：** 你需要存 B站提供的**嵌入链接**（不是普通观看链接）。
    
    JSON
    
    ```
    {
      "type": "video",
      "source": "bilibili",
      "url": "//player.bilibili.com/player.html?bvid=BV1xxxxxx" 
    }
    ```
    
- **优点：** **无需服务器**（流量和存储都是 B站出的），用户体验极好（即开即看）。
    
- **注意：** Chrome 插件对这种“嵌入”有安全限制，开发时需要配置一下权限（Manifest V3 中涉及 CSP 配置），但这不难解决。

## gif
直接引用公共资源（针对 GIF 图）

如果你想显示 GIF 动图，连播放器都不用。

- **体验：** 点开插件，直接显示一张动图。
    
- **原理：** 互联网上有很多**免费图床**或者公开的图片地址。你只需要找到这些图片的网址（URL）即可。
    
- **你的数据存什么：**
    
    JSON
    
    ```
    {
      "type": "image",
      "url": "https://media.giphy.com/media/xhxn/giphy.gif"
    }
    ```
    
- **优点：** 就像浏览网页一样自然。你不需要服务器，你只是在“借用”图片原本所在的地址。
